# 星澜业务助手 · 工作流规范

文档编号：XL-AI-WF-001  
适用范围：钉钉入口的企业内部助手（Chatflow「业务助手」）  
编排平台：自建 Dify 1.16.1  
主模型：硅基流动 DeepSeek-V4-Flash（关闭 thinking）

---

## 1. 产品定位

员工在钉钉用自然语言提问。系统先做意图分类，再进入固定支路，**不开放万能 Agent 自行选工具**。

| 能力 | 数据来源 | 回答原则 |
| --- | --- | --- |
| OA / 规章制度 | 知识库（OA 流程 + 制度） | 只依据检索片段；未命中则标准拒答，不口头补条款 |
| 客户档案 | 知识库（客户主数据） | 只依据档案；未命中则请销售中心补录 |
| 经营取数 | `nanjiren_cate_date` 只读查询 | 模型只生成 SELECT；网关校验执行后直接回传正文，不再二次改写数字 |
| 闲聊 / 能力说明 | 短回复 | 不编造数字和条款 |
| 职责外 | 固定文案 | 引导改问三类职责，或转业务部门 |

数字以库为准，制度和客户以知识库为准，两套来源不得互相编造。

## 2. 要解决的问题

| 场景 | 现状痛点 | 助手标准动作 |
| --- | --- | --- |
| 流程咨询 | 制度散落、新人反复问 HR / 行政 | 检索后按「结论 → 依据 → 办理路径 → 注意事项」回复 |
| 客户信息 | 接口人、账期、风险要翻档案 | 按客户库检索；没有就承认未收录 |
| 经营数字 | 问渠道/类目金额要找数仓或导表 | NL2SQL + 只读网关，金额以万元展示，可导出 / 出图 |
| 入口 | 员工已在钉钉 | Stream 机器人；会话约 15 分钟记忆 |

## 3. 系统分层

```text
员工 ──钉钉──► dingtalk-bridge（Stream）
                    │
                    │ POST /v1/chat-messages
                    ▼
              Dify API（Chatflow · 业务助手）
                    │
     ┌──────────────┼──────────────┬────────────┐
     ▼              ▼              ▼            ▼
  知识库 RAG     生成 SELECT      闲聊 LLM    职责外固定文案
     │              │
     │              ▼
     │        query-gateway（校验 + 只读执行）
     │              │
     │              ▼
     │        MySQL njds_data.nanjiren_cate_date
     ▼
  文本结论；Excel/PNG 由网关生成，桥接服务以钉钉文件发出
```

| 组件 | 职责 |
| --- | --- |
| Dify Web / API | 编排、发布、对话、知识库 |
| `dingtalk-bridge` | 钉钉消息 ↔ Dify；解析隐藏标记后发 xlsx / png |
| `query-gateway` | 收 SQL 草稿、安全校验、查库、写回复和文件 |
| 三个 Dataset | OA 流程、客户档案、规章制度 |
| SiliconFlow | 分类、RAG 作答、SQL 生成 |

**约束：大模型不直连业务库。** 凭证、表白名单、LIMIT、只读会话均在网关。

## 4. Chatflow 编排标准

应用类型：`advanced-chat`。节点 ID 只用字母、数字、下划线（模板变量不支持连字符）。

### 4.1 主链路

```text
用户输入
  → 意图识别 intent
       ├─ oa        → 检索 OA+制度 → 是否命中？ 未命中→标准拒答 / 命中→LLM（结论-依据-路径）
       ├─ customer  → 检索客户     → 是否命中？ 未命中→标准拒答 / 命中→LLM（结论-依据-待办）
       ├─ sql       → LLM 生成 SELECT → HTTP 网关（失败重试 2 次）
       │                → HTTP 200 → 原样回复网关正文
       │                → 非 200  → 取数失败标准文案
       ├─ chitchat  → LLM 能力说明
       └─ oos       → 职责外标准文案（不调用模型）
```

经营取数支路**禁止**再用 LLM 润色数字。Answer 节点输出 `{{#http_sql.body#}}`。

### 4.2 意图分类

分类器只打标签。带 8 轮对话记忆，处理「那家客户」「还要谁批」。

| 类别 | 进入条件 | 不得进入 |
| --- | --- | --- |
| oa | 请假、报销、用印、入职、加班等流程制度 | 某客户账期（走客户档案） |
| customer | 指定客户的接口人、合同、SLA、档案内回款风险 | 「这个月华东支付多少」（走取数） |
| sql | 渠道/类目/店铺金额、汇总、导出、直方图 | 制度条款 |
| chitchat | 你好、你是谁、谢谢 | 含业务信息的问句 |
| oos | 改库、绕过审批、未建档猜测、天气/炒股/写代码等 | 三类职责内问题 |

边界规则写入分类 instruction：**档案事实归 customer/oa，报表数字归 sql。** 「回款」一词不得同时打到档案风险和 SQL 汇总。

### 4.3 RAG 作答标准

命中后的 LLM 必须：

- 只依据检索结果，禁止编造审批人、金额、接口人。
- OA：结论 → 依据（文档名/条款）→ 办理路径 → 注意事项。
- 客户：结论 → 依据 → 风险或待办 → 下一步（谁补录）。
- 检索为空：**不经过 LLM**，直接输出规范拒答，避免空上下文编造。

### 4.4 发布纪律

- 编辑器跑的是草稿；钉钉打的是**已发布**版本。改完必须发布。
- 不要用旧画布覆盖保存（HTTP `retry_interval` 曾被写成 0.5，后端只接受整数）。
- 画布保存后若编排页 502，先查 Nginx 是否仍指向已重建的 API 容器，**编排失败不等于工作流被删除**。

## 5. 知识库

语料目录：`knowledge-bases/`。切分：按标题 400–800 字；制度按条款；客户按档案。

| 知识库 | 内容 |
| --- | --- |
| 星澜-OA内部流程 | 请假考勤、差旅、报销付款、采购、用印、入职离职、IT、加班会议室等 |
| 星澜-公司客户资料 | 客户分级、KA 档案、回款与商机 |
| 星澜-公司规章制度 | 员工手册、信息安全、反贿赂、财务纪律、招聘培训等 |

检索：多路召回，top_k=8。当前为**经济模式 / 关键词**（高质量向量所用 Embedding 接口曾返回 403）。中文专名、条款编号关键词可用；近义词（「年假」与「带薪年休假」）召回偏弱。修复 Embedding 权限后应切高质量向量，并视情况加 Rerank。

回归问句见各目录 `00-检索测试问句.md`（用作验收用例，不是给员工看的说明书）。

## 6. 经营取数（NL2SQL）

### 6.1 数据范围

- 库：`njds_data`，表：`nanjiren_cate_date`
- 约 25.9 万行，统计日约 2025-01-01 ～ 2026-08-02
- 核心字段：`sta_date` / `year`/`month`/`day`，`cate`，`internal_cate`，`channel`，店铺，实控人/负责人，`pay_amount`
- **业务日期只用 `sta_date`/`year`，不用 `create_time`**

渠道示例：拼多多、天猫、抖音、京东、唯品会、视频号、快手等。  
类目示例：内衣、服饰配件、男装、女装等。  
金额展示：元 ÷ 10000，保留 1 位，单位万元。  
「今年」在 SQL 生成提示中固定为 **year=2026**（业务日按 2026-09-07 理解）。

### 6.2 执行链路

1. 分类到 sql。  
2. LLM 只输出一条 SELECT。  
3. HTTP 以 **x-www-form-urlencoded** 提交用户问题与 SQL 草稿（避免 JSON 套引号损坏）。失败重试 2 次，间隔 1 秒。  
4. 网关解析、校验、执行、写回复；导出/出图时带 `[[DIFY_EXCEL:...]]` / `[[DIFY_CHART:...]]`。  
5. 钉钉桥解析标记，内网下载后以文件发出。  
6. 网关对常见汇总问法有 fallback SQL，避免解析失败整路空白。

### 6.3 安全控制

| 措施 | 说明 |
| --- | --- |
| 模型不持有库密码 | 凭证只在网关环境变量 |
| 只允许 SELECT / WITH | 拦截写操作、UNION、JOIN、多语句、注释等 |
| 表白名单 | FROM 只能是 `nanjiren_cate_date` |
| 强制 LIMIT | 缺省补上，上限 200 行 |
| 会话只读 | `SET SESSION TRANSACTION READ ONLY`，限制执行时间 |
| 鉴权 | 网关 Bearer Token，Dify HTTP 节点携带 |
| 导出 | 随机 token、约 15 分钟过期；员工侧走钉钉文件，不发办公网段直链 |

生产应使用仅 `SELECT` 该表的专用账号，避免高权限账号。

### 6.4 导出与图

- Excel：openpyxl；钉钉发文件。不向员工下发仅内网可开的 `192.168.x.x:8787` 链接。  
- 直方图：matplotlib 出 PNG 当文件发。不用 Mermaid（钉钉/Dify 渲染不稳定）。  
- 容器需挂载中文字体（如 SimHei）并指定 `FontProperties`。  
- 钉钉 image 消息需要公网 `picURL`，内网 PNG 会失败，因此直方图走 **file + png**。  
- 用户未明确要求图表时不出图。

## 7. 钉钉通道

- 企业自建应用 Stream 模式。  
- 桥接：blocking 调用 Dify `chat-messages`；按发送者 + 会话记住 `conversation_id`，默认约 15 分钟。  
- 超长文本截断；模型/接口错误转中文说明。  
- 多行结论用 reply_text 保留换行（markdown 在钉钉里易被收成一行）。

## 8. 模型参数

| 节点 | temperature | max_tokens | 说明 |
| --- | --- | --- | --- |
| 意图识别 | 0 | 64 | 只要标签 |
| SQL 生成 | 0 | 400 | 只要一条 SELECT |
| OA / 客户作答 | 0.2 | 2048 | 关闭 thinking |
| 闲聊 | 0.2 | 512 | 一两句能力说明 |

关闭 thinking：钉钉只要可执行结论，减少超时和 token。

## 9. 运维与已处理故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 钉钉原文出现 `{{#llm_chat.text#}}` 一类占位符 | 节点 ID 含 `-`，模板抽不到变量 | ID 仅用 `[a-zA-Z0-9_]` |
| 提示「库里没数」但库中有数 | SQL 放进 JSON body 引号损坏 | SQL 纯 SELECT；HTTP 改表单；网关 fallback |
| 调用模型失败且提示 retry_interval | 画布默认 0.5，后端只要整数 | 间隔用整数；服务端可把 float 收成 int |
| 刷新工作流转圈、应用像消失 | API 容器重建后 Nginx 仍打旧 IP（502） | 重启 Nginx；硬刷新。数据在 Postgres |
| 直方图代码无效 | Mermaid `xychart-beta` 不完整 | 服务端出 PNG |
| `miss param picURL` | image 消息要公网图链 | 按文件发 png |
| 图上中文方块 | 容器无中文字体 | 挂载黑体并指定字体 |
| Embedding 403 | 向量索引建失败 | 先关键词可答，再补向量 |

## 10. 迭代清单

| 现状 | 风险 | 下一步 |
| --- | --- | --- |
| 仅一张日销表 | 库存、回款明细问不了 | 按主题扩表白名单，不开放全库 |
| 可能仍用高权限库账号 | 权限过大 | 只读账号 + IP 限制 |
| SQL 校验偏正则 | 复杂语句误杀或漏拦 | sqlglot 等 AST 校验 |
| RAG 关键词 | 同义问法不稳 | Embedding + Rerank + 验收问句回归 |
| 分类靠 LLM | 边界句可能分错 | 日志抽检；高频错分加规则或示例 |
| 经营数据未按角色过滤 | 权限过宽 | 身份、事业部过滤、字段脱敏 |

## 11. 上线验收用例

按顺序各跑一条，核对来源是否正确、空结果是否拒答、数字是否与网关一致。

1. OA：「请假超过 3 天要谁审批？」→ 有文档依据，不编造。  
2. 客户：「宁泊汽车的客户成功经理是谁？」→ 档案有则答，没有则未收录。  
3. 取数：「2025 年抖音渠道内衣支付金额多少？」→ 单个数字，单位万元。  
4. 导出：「按渠道汇总今年支付金额并导出 Excel」→ 分行万元 + 钉钉文件。  
5. 图：「按渠道汇总今年 1–7 月支付金额并用直方图展示」→ 正文 + PNG，中文不是方块。  
6. 职责外：「帮我写一段 Python 爬虫」→ 固定引导，不调用取数。  
7. 空检索：问一条知识库明显没有的制度细节 → 标准拒答，不编条款。
